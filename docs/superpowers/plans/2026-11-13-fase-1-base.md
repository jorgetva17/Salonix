# Salonix — Fase 1 (Base) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar a base multi-tenant do Salonix: projeto rodando, Supabase local, cadastro de salão com admin, login/recuperação de senha, convites de equipe com perfis, layout responsivo com navegação por perfil, tema claro/dark persistido, logo padrão + upload de logo do salão e PWA instalável.

**Architecture:** Next.js App Router (Server Components para leitura, Server Actions para escrita) sobre Supabase local (Docker). Isolamento por `salon_id` + RLS com funções auxiliares `is_salon_member` / `has_salon_role`; operações que envolvem várias tabelas são RPCs Postgres. O salão ativo do usuário fica num cookie.

**Tech Stack:** Next.js (última estável, App Router, `src/`), TypeScript strict, Tailwind CSS, shadcn/ui, `@supabase/ssr` + `@supabase/supabase-js`, Supabase CLI (devDependency `supabase`), Zod, next-themes, sharp (só script), Vitest + Testing Library, pgTAP (`supabase test db`), Playwright.

**Spec:** `docs/superpowers/specs/2026-11-13-salonix-mvp-design.md`

## Global Constraints

- Toda a UI e mensagens (inclusive erros de validação) em **pt-BR**.
- Moeda BRL; valores monetários em **centavos (integer)** no banco e no código.
- Timestamps `timestamptz` (UTC); exibição no fuso do salão, padrão `America/Sao_Paulo`.
- Toda tabela com `salon_id` tem RLS habilitado e policies cobertas por teste pgTAP.
- Perfis: `admin`, `reception`, `professional` (enum `salon_role`).
- Cores: primária `#1B3B4B`, destaque `#F59E0B`.
- Mobile-first: rodapé de navegação < 768px, sidebar ≥ 768px; alvos de toque ≥ 44px.
- Estados de loading, vazio e erro em toda tela.
- Logo do salão: PNG/JPG/SVG, máx. 2 MB, exibida só via `<img>` (SVG nunca inline).
- Service role key só em código server (`import "server-only"`), nunca em `NEXT_PUBLIC_*`.
- Commits em português, no estilo `feat: ...`, terminando com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Cadastro em que a criação do salão falha** (ex.: erro de rede depois de criar o usuário) — o usuário deve cair em `/onboarding` e conseguir criar o salão, nunca ficar preso sem salão. → teste e2e na Task 5.
2. **Convite para e-mail que já tem conta** — `inviteUserByEmail` falha nesse caso; o convite deve continuar valendo e aparecer ao fazer login. → teste pgTAP de `accept_invite` + teste de action na Task 6.
3. **Membro desativado** perde acesso imediatamente (RLS checa `active`), mesmo com sessão aberta. → pgTAP na Task 3.
4. **Nomes com acento e duplicados** ("Barbearia São João" duas vezes) geram slugs `barbearia-sao-joao` e `barbearia-sao-joao-2`. → pgTAP na Task 3.
5. **Upload de logo inválido** (PDF renomeado para .png, arquivo de 3 MB, SVG com `<script>`) é rejeitado com mensagem clara; SVG aceito nunca é renderizado inline. → testes na Task 9.
